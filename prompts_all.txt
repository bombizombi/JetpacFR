Can you change the trace file format in recording and in displaying it, in the following way.  Right now, we take a state snapshot after every frame, and we do not record anything in between frames for save. Also, when displaying trace file, and the trace file is freshly loaded, we have to emulate all the frames to be able to display the trace in the flame graph.  So, now we need to change this to work this way:  
- When recording the trace, the state is saved every frame for first 10 seconds (10 seconds to be configurable), and after that, each second.  (This will save some memory and disk).
- When displaying the flame graph, not all frames should be emulated, only those whose pixels are actually needed to be displayed should be emulated.  We determine this requirement from the pixel size of the target flame graph size, and calculate a "probe" every pixel and calculate which frame whould this pixel actually hit. (Perhaps use the strategy to select the earlies frame this pixel would hit).  Also, when fully zoomed out, (so when we display the full graph) we do not need a per pixel resolution.  We can approximate the graph with 8 pixel resolution, so each emulated frame gets spread over 8 pixels. (this 8 pixels should also be configurable). And only when we are zoomed at the level where each frame is taking the space of more than one pixel should we switch to the full resolution, where we display (and calculate) as many frames as there are horizontal pixels in the target graph. This once per second strategy will reduce the file size greatly, but will cause the minimum emulation requrement to grow to one second per 1 pixel or 8 pixels, so we also need a hybrid strategy where longer frame gaps are intermingled with short 1 frame states, and when looking for a target frame from the pixel location, we should first search for those short frames and execute them.
-Addional requirement, when in long file mode, we should alternate between short snapshot (one frame only) and long frame (one second), and when a drawing request comes, or the jump to code request comes, the request should always contain the range of instruction count (earliest instruction count that this pixel covers and latest instruction count that this pixel covers).   Also, short frame should store, along with the full snapshot, a frame summary, which should be really short (just one rectangle per stack level), so that drawing could be instant for that request.
-In whichever zoom level we are positioned, and no matter if we already emulated this frame or not, when we click on the flame graph, the position in the timeline, the instruction under the cursor should be shown in the code window, in both execution mode and in the memory mode.
-One of the goals of this redesign is to have almost instant display of the graph at any zoom level.  

What do you think about this change, did I miss any obvious ideas or improvements?  Give me ideas even if they are not obvious or easy.
