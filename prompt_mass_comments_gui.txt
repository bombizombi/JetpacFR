instructions for testing





 Creating a new Z80 disassembly project

 Everything runs from the repo root C:\cs\Spectrum_emulator\Jetpac_FreeRange. Addresses are decimal on the CLI and in
 control.json ($4000 = 16384, $8000 = 32768).

 ### 0. One-time: build the generator host

 ```
dotnet build tests/JetpacFR.Core.Tests
 ```

 ### 1. Scaffold the project

 ```
dotnet run --project tests/JetpacFR.Core.Tests --no-build -- --gen-game games/mygame --from C:\path\to\your.bin --address
32768 --name MyGame
 ```

 - --address = the load address your code expects (default 32768). For code meant to run at $4000, pass 16384.
 - The directory name (mygame) becomes the project's GameId — keep it lowercase ASCII.

 This creates:

 +-----------------------------------+------------------------------------------------------------------------------------+
 | File                              | Content                                                                            |
 +-----------------------------------+------------------------------------------------------------------------------------+
 | games/mygame/original.bin         | your image, normalized                                                             |
 +-----------------------------------+------------------------------------------------------------------------------------+
 | games/mygame/control.json         | span [start, endExcl) detected from last non-zero byte, entryPc = load address,    |
 |                                   | activeVersion: 0, one whole_span code block                                        |
 +-----------------------------------+------------------------------------------------------------------------------------+
 | games/mygame/versions/v000_init.f | the first disassembly                                                              |
 | s                                 |                                                                                    |
 +-----------------------------------+------------------------------------------------------------------------------------+

 (--from also accepts .sna: memory lands at $4000, entry PC popped off the stack.)

 ### 2. Add a manifest so the interpreter side can boot it

 Create games/mygame/manifest.json:

 ```json
{
  "name": "MyGame",
  "program": { "bin": "original.bin", "address": 32768 },
  "boot": "program"
}
 ```

 "address" must match your --address. Now the game appears in the desktop game combo and boots by loading the image at that
 address, PC = address.

 ### 3. Read the first disassembly

 Open versions/v000_init.fs. Each line is one instruction of the CE DSL:

 - covered instructions → named ops: Z80Vocab.LD_A 0x05, Z80Vocab.OUT_n_A 0xFE, ...
 - jump targets → symbolic labels: Z80.at lbl3 marks the spot, Z80.JR_Z_LBL lbl3 references it (labels are local to the
   version)
 - undecodable bytes → merged raw blocks: yield! [| 0x..uy; ... |] (these run through the interpreter)

 This file is your disassembly — it never gets edited by hand; you regenerate it.

 ### 4. Mark blocks in control.json

 Edit the blocks array to say what each region is:

 ```json
"blocks": [
  { "start": 32768, "endExcl": 33024, "name": "main_loop", "kind": "code" },
  { "start": 33024, "endExcl": 33152, "name": "screen_data", "kind": "data" },
  { "start": 33152, "endExcl": 33280, "name": "padding", "kind": "gap" },
  { "start": 33280, "endExcl": 33923, "name": "routines", "kind": "code" }
]
 ```

 Rules the loader enforces:
 - blocks must exactly tile [start, endExcl) — no holes, no overlap, no uncovered tail. Unmapped padding gets kind: "gap"
   (emitted as one raw block with a comment), don't just leave it out.
 - code = disassemble instruction-by-instruction; data/gap = single labeled raw block.
 - boundaries land exactly where you mark them, so data regions stop the disassembler from garbage-decoding through tables.

 ### 5. Regenerate and compare

 ```
dotnet run --project tests/JetpacFR.Core.Tests --no-build -- --regen games/mygame --tag marked-data-blocks
dotnet run --project tests/JetpacFR.Core.Tests --no-build -- --diff-game games/mygame v000 v001
 ```

 - --regen writes versions/v001_marked-data-blocks.fs, bumps activeVersion, and materializes it to CeProgram.fs.
 - The parity gate: before writing, the generator re-assembles the span and refuses anything that wouldn't reproduce
   original.bin byte-for-byte. Your disassembly can't silently rot.
 - --diff-game prints per-version status: PARITY OK, N ops, raw M% — the raw percentage is your lifting progress metric.

 ### 6. Switch versions

 Any old version stays on disk forever. To make an older one active again: set "activeVersion": 0 in control.json, then

 ```
dotnet run --project tests/JetpacFR.Core.Tests --no-build -- --materialize games/mygame
 ```

 ### 7. Iteration loop while marking up (optional)

 ```
powershell -File tools/watchgame.ps1 -GameDir games/mygame            # one pass: materialize + fable
powershell -File tools/watchgame.ps1 -GameDir games/mygame -Watch     # loop on changes
 ```

 ### 8. Running THIS game under the CE engine in a shell (manual, follows the minimal template)

 Shell binaries only see games compiled into them. To wire yours in:

 1. Create games/mygame/Image.fs:
    ```fsharp
module MyGame.Image
open Jetpac2.Core
open Jetpac2.Core.Z80BuilderInstance
let program : Z80Op list = z80 {
// <- paste the body of versions/vNNN_*.fs (the active one) here
}
    ```
 2. Create games/mygame/JetpacFR.Game.MyGame.fsproj copying games/minimal/JetpacFR.Game.Minimal.fsproj (Compile list = your
    Image.fs; ProjectReference to src/Jetpac2.Core). Note: netstandard2.0, Jetpac2.Core only — game projects stay
    Fable-clean.
 3. Reference the fsproj from src/JetpacFR.Desktop/JetpacFR.Desktop.fsproj, and add a GameRegistry.register { GameId =
    "mygame"; Name = "MyGame"; Memory = <64K entry image>; BaseAddress = 32768; Program = MyGame.Image.program; EntryState
    = <reset state string> } block next to the existing minimal registration in App.fs (~line 1448).
 4. Rebuild the desktop app; the engine toggle now works for your game whenever its GameId is registered.

 ### Troubleshooting

 +-------------------------------------------+----------------------------------------------------------------------------+
 | Symptom                                   | Cause                                                                      |
 +-------------------------------------------+----------------------------------------------------------------------------+
 | gap before block X (...)                  | blocks don't tile the span — cover the hole with a gap block               |
 +-------------------------------------------+----------------------------------------------------------------------------+
 | parity FAILED at XXXX - refusing to write | bug in the generator's emission; report it — never hand-fix the version    |
 |                                           | file                                                                       |
 +-------------------------------------------+----------------------------------------------------------------------------+
 | activeVersion N has no versions/vNNN_*.fs | typo'd index or deleted version                                            |
 +-------------------------------------------+----------------------------------------------------------------------------+
 | game doesn't appear in the combo          | missing/malformed manifest.json in games/mygame/                           |
 +-------------------------------------------+----------------------------------------------------------------------------+
 | engine toggle disabled for your game      | no registry registration in the shell yet (step 8)                         |
 +-------------------------------------------+----------------------------------------------------------------------------+
