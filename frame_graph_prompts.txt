## 2. Can it actually never finish?

No loop is infinite — every walk advances an address pointer by at least 1 byte and is capped at 64K, and the element loops are bounded by the instruction count. But two things make it *effectively* endless:

- **Cache invalidation while the machine runs.** The rebuild cache is keyed on `(s.Frame, s.Recorder.SelfModCount)` (App.fs:945-948). If the emulator is playing, recording, or cinema-scrolling while graph mode is on, every timer tick (30–100 ms) calls `refreshDisasm → buildGraph`, sees a changed epoch, and starts the whole multi-minute rebuild **again from scratch**. The app never gets a tick where the graph is considered "done", so it looks like it never finishes — it's the same enormous job restarting forever.
- **The 1-second TTLs.** `flowBlocks` (the `splitBlocks` sweep, the O(instructions × targets) hot spot from my earlier analysis) is cached for only 1 second (App.fs:746), so any follow-up interaction a second later re-pays the sweep even when nothing changed.

Your VS break at line 1008 confirms it was grinding in the per-instruction `TextBlock` creation loop — with the default 48 KB span that's ~20,000+ elements, each also paying a linear `commentAt` scan. So: finite, but minutes per build, and unbounded in wall-clock time when playback keeps re-triggering it. (That combination — pause the emulator before switching to Graph — will at least make it a one-time wait until the underlying performance issues are fixed.)

## 3. Replay file format (short summary)

The recorded keypresses live in **`replay.json`** in each game's directory ([Replay.fs](src/JetpacFR.Core/Replay.fs)):

- **JSON, versioned object**: `{"format": "jetpacfr-replay", "version": 1, "gameId": "...", "assetFingerprint": {...}, "events": [...]}` — hand-serialized, not via a type serializer.
- **Each event**: `{"frame":N, "row":N, "bit":N, "pressed":bool}` — frame number (50 fps), which keyboard matrix row (0–7) and bit (0–4) of the Spectrum keymap, and whether it's a press or release.
- **Asset fingerprint**: SHA-256 hashes of the ROM, TZT/tape, and optional program image plus the program address, so a recording is never auto-replayed against different assets.
- **Safety**: saved atomically (write `.tmp`, then move). On load, format/version/gameId/fingerprint are all validated; any mismatch → `ReplayIgnored` and the file is skipped rather than half-applied. A legacy bare event-array format is accepted as a one-time import.
